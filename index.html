📗 Módulo 2 — Costos, AWS Organizations y soporte

💰 Modelo de precios de AWS

Módulo 2 · Costos

Informática

  • Se cobra por hora o segundo.
  • Varía según el tipo de instancia.
  • La diapositiva señala esta modalidad para Linux.

Idea rápida: Pagas por el tiempo de uso del recurso de cómputo.

Módulo 2 · Costos

Almacenamiento

  • Normalmente se cobra por GB.
  • El precio puede variar según el servicio y el volumen utilizado.

Idea rápida: Pagas principalmente por la cantidad de almacenamiento utilizado.

Módulo 2 · Costos

Transferencia de datos

  • Los datos de salida se suman y se cobran.
  • Los datos de entrada son sin cargo, con algunas excepciones.
  • Normalmente se cobra por GB.

Idea rápida: El movimiento de datos, especialmente la salida, puede generar costos.

📉 Descuentos y servicios sin cargo

Costos

Descuentos basados en el volumen

AWS puede ofrecer precios por niveles: a medida que aumenta el uso, el precio por GB puede disminuir en servicios como S3, EBS y EFS.

Comparación: Como comprar más y obtener un precio menor por unidad.

Costos

Servicios sin cargo

La diapositiva incluye Amazon VPC, Elastic Beanstalk, Auto Scaling, AWS CloudFormation e IAM entre los servicios sin cargo.

Importante: Que el servicio aparezca sin cargo no significa que todos los recursos utilizados junto con él sean gratuitos.

🏢 Infraestructura tradicional vs. nube de AWS

Módulo 2

Nube de AWS

El material contrasta la infraestructura tradicional, que requiere equipos, recursos, administración, contratos y costos, con la nube de AWS.

Características mostradas: Sin gastos iniciales, pagar por lo que se utilice, mejorar el plazo de comercialización, ganar agilidad, escalar bajo demanda e infraestructura de autoservicio.

💵 Costo total de propiedad (TCO)

Costos

TCO — Costo total de propiedad

Es una estimación financiera que ayuda a identificar los costos directos e indirectos de un sistema.

¿Para qué sirve? Para comparar el costo de ejecutar una infraestructura completa o una carga de trabajo en instalaciones con el costo de hacerlo en AWS.

También: Se utiliza para presupuestar y desarrollar el caso de negocio para migrar a la nube.

📌 Conceptos adicionales que pueden aparecer

Importante: estos conceptos no aparecen en las diapositivas que me proporcionaste, pero están relacionados con el tema de precios de AWS y pueden aparecer en evaluaciones.
Adicional

Reserved Instances

Opción de compra de capacidad para ciertos servicios como Amazon EC2 y Amazon RDS, con un compromiso de uso durante un periodo determinado.

Idea rápida: Se reserva capacidad para obtener un modelo de precio diferente al de uso bajo demanda.

Adicional

AURI — All Upfront

Se paga el costo completo de la instancia reservada por adelantado.

Idea rápida: Todo el pago al inicio.

Adicional

PURI — Partial Upfront

Se realiza un pago parcial por adelantado y el resto se paga según las condiciones de la reserva.

Idea rápida: Una parte al inicio y el resto después.

Adicional

NURI — No Upfront

No requiere un pago inicial por adelantado para la instancia reservada.

Idea rápida: Sin pago inicial.

📙 Módulo 3 — Infraestructura y regiones de AWS

Regiones de AWS

Infraestructura

Región de AWS

Una región de AWS es una zona geográfica donde AWS proporciona infraestructura y servicios.

Idea rápida: Es una ubicación geográfica que agrupa infraestructura de AWS.

Regiones

Replicación entre regiones

La replicación de datos entre regiones es controlada por el usuario.

Idea rápida: Tú decides si y cómo replicar los datos entre regiones.

Regiones

Comunicación entre regiones

La comunicación entre regiones utiliza la infraestructura de red troncal de AWS.

Idea rápida: Las regiones se comunican mediante la red troncal de AWS.

Regiones

Redundancia y conectividad

Cada región proporciona a la red niveles plenos de redundancia y conectividad.

Idea rápida: La región está diseñada para ofrecer conectividad y redundancia.

Selección de una región

Selección

Gobernanza de datos y requisitos legales

La selección de una región debe considerar la gobernanza de los datos y los requisitos legales.

Idea rápida: Verifica dónde pueden almacenarse y procesarse los datos.

Selección

Proximidad con los clientes

La cercanía de la región con los clientes puede influir en la latencia.

Idea rápida: Una región más cercana puede reducir la latencia.

Selección

Servicios disponibles

La región debe contar con los servicios necesarios para las aplicaciones y datos.

Idea rápida: No todos los servicios tienen que estar disponibles en todas las regiones.

Selección

Costos por región

Los costos pueden variar según la región seleccionada.

Idea rápida: La misma solución puede tener costos diferentes según la región.

Zonas de disponibilidad

Infraestructura

Zona de disponibilidad (Availability Zone)

Es una partición completamente aislada de la infraestructura de AWS dentro de una región.

Idea rápida: Es una zona aislada dentro de una región para ayudar a separar fallos.

Zonas de disponibilidad

Centros de datos discretos

Las zonas de disponibilidad constan de centros de datos discretos y están diseñadas para el aislamiento de errores.

Idea rápida: Separar centros ayuda a limitar el impacto de un error.

Zonas de disponibilidad

Interconexión de zonas

Las zonas de disponibilidad se interconectan con otras mediante redes privadas de alta velocidad.

Idea rápida: Las zonas están separadas, pero conectadas rápidamente.

Resiliencia

Replicación entre zonas

AWS recomienda replicar los datos y recursos entre las zonas de disponibilidad para obtener mayor resiliencia.

Idea rápida: Tener recursos en varias zonas ayuda frente a fallos.

Puntos de presencia

Redes

Puntos de presencia

AWS proporciona una red global de puntos de presencia. En el material se indican 187 ubicaciones: 176 ubicaciones de borde y 11 cachés de borde regionales.

Idea rápida: Son ubicaciones distribuidas que acercan contenido a los usuarios.

Redes

Amazon CloudFront

Es una red de entrega de contenido (CDN) global que entrega contenido a los usuarios finales con latencia reducida.

Idea rápida: Acerca el contenido al usuario para reducir la latencia.

Redes

Cachés de borde regionales

Se utilizan para contenido con acceso poco frecuente.

Idea rápida: Son cachés intermedias para contenido que no se solicita constantemente.

Características de la infraestructura de AWS

Infraestructura

Elasticidad

La infraestructura elástica permite una adaptación dinámica de la capacidad.

Idea rápida: La capacidad puede adaptarse a las necesidades.

Infraestructura

Escalabilidad

La infraestructura escalable se adapta para admitir crecimiento.

Idea rápida: Permite crecer cuando aumentan las necesidades.

Infraestructura

Tolerancia a errores

Es la capacidad de mantener el funcionamiento correcto en presencia de un error, con redundancia integrada de los componentes.

Idea rápida: Un error no debería detener todo el funcionamiento.

Infraestructura

Alta disponibilidad

Busca un alto nivel de rendimiento operativo, minimizar el tiempo de inactividad y funcionar sin intervención humana.

Idea rápida: Mantener los servicios disponibles durante el mayor tiempo posible.
