Módulo 2 · Costos

Informática

  • Se cobra por hora o segundo.
  • Varía según el tipo de instancia.
  • La diapositiva señala esta modalidad para Linux.

📌 Conceptos adicionales que pueden aparecer

Adicional

Reserved Instances

Opción de compra de capacidad para ciertos servicios como Amazon EC2 y Amazon RDS, con un compromiso de uso durante un periodo determinado.

Idea rápida: Se reserva capacidad para obtener un modelo de precio diferente al de uso bajo demanda.

Adicional

NURI — No Upfront

No requiere un pago inicial por adelantado para la instancia reservada.

Idea rápida: Sin pago inicial.

Infraestructura

Región de AWS

Una región de AWS es una zona geográfica donde AWS proporciona infraestructura y servicios.

Idea rápida: Es una ubicación geográfica que agrupa infraestructura de AWS.

Regiones

Replicación entre regiones

Idea rápida: Tú decides si y cómo replicar los datos entre regiones.

Regiones

Comunicación entre regiones

Idea rápida: Las regiones se comunican mediante la red troncal de AWS.

Regiones

Redundancia y conectividad

Cada región proporciona a la red niveles plenos de redundancia y conectividad.

Idea rápida: La región está diseñada para ofrecer conectividad y redundancia.

Selección de una región

Selección

Gobernanza de datos y requisitos legales

La selección de una región debe considerar la gobernanza de los datos y los requisitos legales.

Idea rápida: Verifica dónde pueden almacenarse y procesarse los datos.

Selección

Proximidad con los clientes

Idea rápida: Una región más cercana puede reducir la latencia.

Selección

Idea rápida: No todos los servicios tienen que estar disponibles en todas las regiones.

Selección

📕 Módulo 4 — Seguridad y responsabilidad en AWS

Contenido del Módulo 4: este módulo explica el modelo de responsabilidad compartida, IAM, autorización, protección de cuentas, cifrado, protección de Amazon S3 y conformidad. Los servicios que ya aparecían en módulos anteriores se complementan en sus propias tarjetas en lugar de duplicarse.

Modelo de responsabilidad compartida

Seguridad

Modelo de responsabilidad compartida

La seguridad y la conformidad son una responsabilidad compartida entre AWS y sus clientes.

Idea rápida: AWS protege la infraestructura de la nube y el cliente protege lo que configura y utiliza dentro de ella.

AWS

Responsabilidad de AWS

AWS es responsable de la seguridad de la nube: seguridad física de los centros de datos, infraestructura de hardware y software, infraestructura de red e infraestructura de virtualización.

Incluye: centros de datos, equipos, red, virtualización, regiones, zonas de disponibilidad y ubicaciones de borde.

Cliente

Responsabilidad del cliente

El cliente administra aspectos como el sistema operativo de sus instancias, aplicaciones, configuración de red y firewall, cifrado de datos, sistema de archivos y administración de cuentas y permisos.

Idea rápida: El cliente es responsable de la seguridad dentro de la nube según el servicio que utilice.

IaaS

Responsabilidad de seguridad en IaaS

En IaaS, el cliente tiene mayor flexibilidad y administra más aspectos de la seguridad, incluida la configuración de redes, almacenamiento y controles de acceso.

Ejemplos del material: Amazon EC2, Amazon EBS y Amazon VPC.

PaaS

Responsabilidad de seguridad en PaaS

En PaaS, el cliente no necesita administrar la infraestructura subyacente. AWS gestiona el sistema operativo, parches de la base de datos, configuración del firewall y recuperación de desastres.

Ejemplos del material: AWS Lambda, Amazon RDS y AWS Elastic Beanstalk.

SaaS

Responsabilidad de seguridad en SaaS

El software está alojado de forma centralizada y el cliente no necesita administrar la infraestructura que respalda el servicio.

Ejemplos del material: AWS Trusted Advisor y Amazon Chime; el acceso puede realizarse mediante navegador, aplicación móvil o interfaz de programación.

IAM: identidad, autenticación y autorización

Persona o aplicación que se puede autenticar con una cuenta de AWS.

Idea rápida: Es una identidad que puede iniciar sesión o realizar solicitudes según sus permisos.

IAM

Grupo de IAM

Colección de usuarios de IAM a los que se concede una autorización idéntica.

Idea rápida: Permite aplicar permisos comunes a varios usuarios.

IAM

Rol de IAM

Mecanismo útil para conceder un conjunto de permisos con el fin de realizar solicitudes de servicios de AWS.

Idea rápida: Un rol proporciona permisos para realizar acciones sin ser un usuario permanente.

IAM

Autenticación de IAM

Es el proceso mediante el cual AWS verifica la identidad antes de permitir el acceso.

Programación: ID de clave de acceso y clave de acceso secreta. Consola: ID de cuenta o alias, nombre de usuario y contraseña; puede utilizar MFA si está habilitado.

IAM

Autorización

Determina qué acciones puede realizar un usuario, grupo o rol sobre los recursos de AWS.

Ejemplo: permitir acceso completo a instancias EC2 o solo lectura a un bucket de S3.

IAM

Política de IAM

Documento que define permisos y habilita un control de acceso detallado.

Tipos mostrados: políticas basadas en identidad y políticas basadas en recursos.

IAM

Política basada en identidad

Se asocia a una entidad de IAM, como un usuario, grupo o rol, y define las acciones que puede o no puede realizar.

Idea rápida: Los permisos se asignan a la identidad.

IAM

Política basada en recursos

Está asociada directamente a un recurso, como un bucket de Amazon S3.

Idea rápida: El permiso se define desde el recurso.

IAM

Denegación explícita e implícita

Los permisos están denegados implícitamente de forma predeterminada. Una denegación explícita nunca permite la acción y prevalece sobre una instrucción de permiso.

Regla: si hay una denegación explícita, se deniega; si no hay permiso explícito, la acción queda denegada implícitamente.

IAM

Principio de mínimo privilegio

Práctica recomendada que consiste en conceder únicamente los permisos necesarios para realizar una tarea.

Idea rápida: No otorgar más acceso del necesario.

Protección de la cuenta de AWS

Seguridad

Usuario raíz de la cuenta de AWS

Es el usuario de la cuenta con acceso total a todos los servicios y recursos de AWS.

Recomendación del material: no utilizarlo salvo cuando sea necesario.

Seguridad

Protección inicial de una cuenta

El material recomienda dejar de utilizar el usuario raíz cuanto antes, crear un usuario de IAM, crear un grupo y asignar permisos, eliminar las claves de acceso del usuario raíz si existen, habilitar una política de contraseñas e iniciar sesión con las nuevas credenciales.

Idea rápida: Crear identidades de IAM y reducir el uso del usuario raíz.

Seguridad

MFA (Multi-Factor Authentication)

Mecanismo que puede solicitar un código adicional de autenticación al acceder a la consola cuando está habilitado.

Idea rápida: Añade un factor de autenticación además de las credenciales.

Registro y facturación

Complemento

AWS CloudTrail en una cuenta nueva

El material indica utilizar AWS CloudTrail para realizar seguimiento de la actividad de los usuarios en la cuenta y permitir auditorías operativas.

Protección: se puede crear un registro de seguimiento y enviar registros a un bucket de Amazon S3 para conservarlos.

Costos

Informe de uso y costo de AWS

Proporciona información sobre el uso de los recursos de AWS y los costos estimados de dicho uso.

Material: AWS entrega los informes en el bucket de Amazon S3 especificado y el informe se actualiza al menos una vez al día.

AWS Organizations y control de servicios

Organizations

Políticas de control de servicios (SCP)

Las SCP ofrecen control centralizado sobre las cuentas de una organización y limitan los permisos disponibles en una cuenta.

Importante: se parecen a las políticas de permisos de IAM, pero una SCP nunca concede permisos; especifica los permisos máximos para una organización.

Cifrado de datos

Cifrado

Cifrado de datos en reposo

Protege datos almacenados físicamente, como datos en disco o cinta, mediante cifrado.

Material: AWS KMS puede ayudar a administrar claves secretas; se muestran Amazon S3, Amazon EBS, Amazon EFS y bases de datos administradas de Amazon RDS como ejemplos.

Cifrado

Cifrado de datos en tránsito

Protege los datos mientras se trasladan a través de una red.

Material: utiliza TLS o SSL para el intercambio bidireccional de datos; HTTPS puede crear un túnel seguro.

Protección de Amazon S3

S3

Protección predeterminada de buckets y objetos S3

Los buckets y objetos de Amazon S3 recién creados son privados y están protegidos de forma predeterminada.

Idea rápida: El acceso público no es el comportamiento predeterminado.

S3

Amazon S3 Block Public Access

Característica de Amazon S3 mostrada como una opción sencilla para controlar y bloquear el acceso público.

Idea rápida: Ayuda a evitar que los datos de S3 queden expuestos públicamente.

S3

Opciones de control de acceso a S3

El material muestra políticas de IAM, políticas de buckets y listas de control de acceso (ACL) como herramientas para controlar el acceso a datos de S3.

Recomendación: seguir el principio de mínimo privilegio y considerar el cifrado de Amazon S3.

Conformidad de AWS

Conformidad

Programas de conformidad de AWS

AWS colabora con organismos de certificación y auditores independientes para ofrecer información detallada sobre políticas, procesos y controles que establece y aplica AWS.

Categorías mostradas: certificaciones y acreditaciones, leyes y regulaciones, y alineaciones o marcos de trabajo.

📓 Módulo 5 — Redes, VPC y entrega de contenido

Contenido del Módulo 5: conceptos de redes de AWS, grupos de seguridad, ACL de red, Amazon Route 53, Amazon CloudFront, VPC, subredes, direccionamiento IP, interfaces de red, tablas de enrutamiento e interconexión de VPC.

Seguridad de red

Seguridad

Grupos de seguridad

Actúan en el nivel de la instancia y controlan el tráfico permitido mediante reglas.

Idea rápida: Funcionan como un filtro de tráfico asociado a una instancia.

Seguridad

ACL de red

Lista de control de acceso que funciona en el nivel de la subred.

Importante: cada subred de una VPC debe estar asociada a una ACL de red; las reglas de entrada y salida son independientes.

Comparación

Security Groups vs. ACL de red

Los grupos de seguridad funcionan a nivel de instancia, mientras que las ACL de red funcionan a nivel de subred.

Diferencia: los grupos de seguridad solo tienen reglas de permiso y mantienen estado; las ACL permiten reglas de permiso y denegación y no mantienen estado.

Amazon Route 53

Redes

Amazon Route 53

Servicio de DNS de alta disponibilidad y escalabilidad que permite registrar nombres de dominio y dirigir usuarios a recursos.

Idea rápida: Traduce nombres de dominio en direcciones y ayuda a dirigir el tráfico.

Route 53

Tipos de direccionamiento de Route 53

Route 53 admite direccionamiento sencillo, de turno rotativo ponderado, basado en latencia, por geolocalización, por geoproximidad, tras conmutación por error y direccionamiento de respuesta multivalor.

Idea rápida: Permiten decidir cómo se dirige el tráfico según pesos, latencia, ubicación, errores o múltiples respuestas.

Amazon CloudFront

Redes

Amazon CloudFront

Servicio de CDN rápido, mundial y seguro que entrega contenido mediante una red global de ubicaciones de borde y cachés de borde regionales.

Modelo: autoservicio y pago por uso.

CloudFront

Infraestructura de CloudFront

Utiliza ubicaciones de borde y cachés de borde regionales para entregar contenido a los clientes con rapidez.

Idea rápida: acerca el contenido a los usuarios para reducir la latencia.

Redes, VPC y subredes

Redes

Subred

División lógica de una red que permite organizar los recursos dentro de una VPC.

Idea rápida: una red puede dividirse lógicamente en varias subredes.

VPC

VPC y subredes

Una VPC es una red virtual aislada lógicamente; sus subredes están dentro de la VPC y pertenecen a una única zona de disponibilidad.

Tipos: las subredes pueden clasificarse como públicas o privadas.

VPC

Direccionamiento IP de una VPC

Al crear una VPC se asigna un bloque CIDR IPv4, que define el intervalo de direcciones IP privadas disponibles.

Material: el bloque CIDR IPv4 más grande mostrado es /16 y el más pequeño /28; también se admite IPv6.

VPC

Dirección IP pública y elástica

La IP pública puede asignarse manual o automáticamente; una IP elástica está asociada a una cuenta de AWS y puede asignarse o reasignarse.

Diferencia: la IP elástica puede mantenerse y reasignarse según sea necesario, aunque puede implicar costos adicionales.

VPC

Interfaz de red elástica (ENI)

Interfaz de red virtual que puede asociarse a una instancia, desasociarse y volver a asociarse a otra instancia para redirigir tráfico.

Idea rápida: los atributos de la interfaz también se asocian cuando se vuelve a asociar a otra instancia.

Enrutamiento e interconexión

Redes

Tabla de enrutamiento

Conjunto de reglas, llamadas rutas, que permite configurar cómo se dirige el tráfico de red de una subred.

Importante: cada ruta especifica un destino y un objetivo; cada subred está asociada a una sola tabla de enrutamiento.

VPC

Uso compartido de VPC

Permite compartir subredes de una VPC con otras cuentas de AWS.

Idea rápida: varios clientes o cuentas pueden utilizar subredes compartidas dentro de una VPC.

VPC

Interconexión de VPC

Permite conectar VPC dentro de una cuenta, entre cuentas de AWS o entre regiones para dirigir tráfico de forma privada.

Restricciones del material: los espacios IP no pueden superponerse, no se admite interconexión transitiva y solo puede existir un recurso de interconexión entre las mismas dos VPC.

Modelo OSI

Redes

Modelo OSI

Modelo de siete capas que describe cómo viajan los datos a través de una red.

Capas: 7 Aplicación, 6 Presentación, 5 Sesión, 4 Transporte, 3 Red, 2 Enlace de datos y 1 Física.

📔 Módulo 6 — Cómputo en la nube y Amazon EC2

Resumen del módulo: este módulo aborda el cómputo en AWS, el aprovisionamiento y la administración de instancias de Amazon EC2, las opciones de precios y optimización de costos, y las alternativas para ejecutar aplicaciones mediante contenedores y servicios administrados.

☁️ Amazon EC2: conceptos fundamentales

Módulo 6 · Cómputo

Amazon EC2

Amazon Elastic Compute Cloud (EC2) proporciona capacidad de cómputo redimensionable en la nube mediante instancias virtuales.

Idea rápida: alquilar un servidor virtual y elegir sus recursos según las necesidades de la aplicación.

EC2

Instancia de EC2

Servidor virtual que ejecuta un sistema operativo y las aplicaciones que se instalan en él.

Idea rápida: es el servidor que se inicia, configura y administra en AWS.

EC2

AMI (Amazon Machine Image)

Imagen que proporciona la información necesaria para iniciar una instancia, como el sistema operativo y la configuración de software inicial.

Idea rápida: una plantilla que sirve como punto de partida para crear instancias.

EC2

Tipo de instancia

Define la combinación de recursos de cómputo disponibles para una instancia, como procesador, memoria, almacenamiento y rendimiento de red.

Elección: depende de las características y necesidades de la carga de trabajo.

EC2

Familias de instancias

Agrupan instancias diseñadas para distintos tipos de cargas de trabajo, por ejemplo uso general, cómputo optimizado, memoria optimizada, almacenamiento optimizado o aceleración de hardware.

Idea rápida: elige la familia según el recurso que más necesita la aplicación.

EC2

vCPU y memoria

La vCPU representa capacidad de procesamiento virtual; la memoria mantiene los datos e instrucciones que las aplicaciones necesitan durante su ejecución.

Idea rápida: más CPU ayuda con el procesamiento y más memoria con cargas que necesitan mantener más datos activos.

🧰 Configuración y lanzamiento de una instancia

Configuración

Lanzamiento de una instancia

El proceso incluye seleccionar una AMI, elegir el tipo de instancia, configurar la red y la seguridad, definir el almacenamiento, agregar etiquetas y revisar los ajustes antes de lanzar.

Orden mental: imagen → tamaño → red → almacenamiento → seguridad → revisión y lanzamiento.

Redes

Configuración de red de EC2

Determina en qué VPC y subred se ejecuta la instancia y cómo se conecta con otros recursos o redes.

Importante: la conectividad depende también de las rutas, direcciones IP y reglas de seguridad.

Seguridad

Grupo de seguridad

Actúa como un firewall virtual asociado a recursos, con reglas que permiten el tráfico de entrada y salida.

Buena práctica: permitir únicamente los puertos y orígenes necesarios.

Seguridad

Par de claves

Conjunto de claves utilizado para autenticar el acceso a instancias. La forma de uso depende del sistema operativo y del método de conexión.

Importante: proteger la clave privada y no compartirla.

Administración

Etiquetas (tags)

Pares de clave y valor que ayudan a identificar, organizar, buscar y administrar recursos de AWS.

Ejemplos: Proyecto, Entorno, Propietario o CentroDeCostos.

EC2

Metadatos de instancia

Información disponible desde la instancia sobre ella misma, como datos de red y otros atributos de configuración.

Idea rápida: información que la instancia puede consultar acerca de su propio entorno.

Seguridad

Rol de IAM para EC2

Permite conceder permisos a aplicaciones que se ejecutan en una instancia sin almacenar claves de acceso permanentes en el código.

Buena práctica: asignar solo los permisos necesarios para la tarea.

💾 Almacenamiento para instancias EC2

Almacenamiento

Amazon EBS

Proporciona volúmenes de almacenamiento de bloques que pueden asociarse a instancias EC2.

Idea rápida: un disco virtual que puede conservar datos independientemente del ciclo de vida de la instancia, según su configuración.

EBS

Volumen raíz y volúmenes de datos

El volumen raíz contiene el sistema operativo de la instancia; los volúmenes adicionales pueden almacenar aplicaciones y datos.

Idea rápida: uno permite iniciar el sistema y los otros amplían el almacenamiento.

Almacenamiento

Almacén de instancias (Instance Store)

Proporciona almacenamiento en discos conectados físicamente al host de la instancia y está destinado a datos temporales.

Diferencia: no debe tratarse como almacenamiento persistente; los datos pueden perderse cuando la instancia se detiene o termina.

EBS

Instantánea (snapshot)

Copia de respaldo de un volumen EBS que permite conservar un punto de recuperación y crear volúmenes a partir de ella.

Idea rápida: guardar una copia para poder recuperar datos después.

Seguridad

Cifrado de EBS

Protege los datos de los volúmenes y las instantáneas mediante cifrado.

Idea rápida: agrega una capa de protección a los datos almacenados.

🔄 Estados y ciclo de vida de EC2

EC2

Estados de una instancia

Durante su ciclo de vida una instancia puede pasar por estados como pendiente, en ejecución, deteniéndose, detenida, apagándose y terminada.

Importante: detener una instancia no es lo mismo que terminarla; la terminación es el cierre definitivo de esa instancia.

EC2 · Costos

Detener e iniciar

Una instancia detenida puede iniciarse de nuevo. La facturación de cómputo y los cargos asociados al almacenamiento siguen reglas distintas.

Idea rápida: detener puede reducir el costo de cómputo, pero no elimina necesariamente todos los cargos.

EC2

Terminar una instancia

Finaliza de forma permanente la instancia. La conservación de los volúmenes y los datos depende de la configuración de eliminación de cada volumen.

Precaución: revisar los datos y las opciones de almacenamiento antes de terminarla.

Redes

Dirección IP elástica

Dirección IPv4 pública estática que puede asociarse a recursos compatibles y reasignarse según sea necesario.

Idea rápida: una dirección pública que puedes conservar y mover entre recursos compatibles.

Monitoreo

Amazon CloudWatch

Permite supervisar métricas y configurar alarmas para observar el comportamiento de recursos como las instancias EC2.

Ejemplo: vigilar el uso de CPU para detectar una carga elevada.

💰 Opciones de precios de EC2

Precios

Instancias bajo demanda

Permiten utilizar capacidad de EC2 sin un compromiso de compra a largo plazo.

Convienen cuando: la carga de trabajo es impredecible o se necesita flexibilidad.

Precios

AWS Savings Plans

Modelo de precios que ofrece tarifas reducidas a cambio de comprometerse a una cantidad de uso de cómputo durante un plazo.

Convienen cuando: se prevé un uso constante y se puede asumir un compromiso.

Precios

Instancias reservadas

Opción de precios que puede ofrecer descuentos a cambio de un compromiso de uso durante un periodo determinado.

Idea rápida: comprometerse con anticipación puede reducir el precio frente a la tarifa bajo demanda.

Precios

Instancias de spot

Permiten utilizar capacidad de EC2 disponible con descuentos, pero pueden sufrir interrupciones cuando AWS necesita recuperar esa capacidad.

Convienen para: trabajos flexibles que pueden tolerar interrupciones.

Precios

Hosts dedicados

Servidores físicos dedicados al uso de un cliente, útiles cuando se necesita mayor visibilidad sobre la ubicación de las instancias o requisitos específicos de licencias.

Idea rápida: el servidor físico se reserva para un solo cliente.

Precios

Instancias dedicadas

Instancias que se ejecutan en hardware dedicado a un único cliente, sin proporcionar el mismo nivel de control sobre el servidor físico que un host dedicado.

Diferencia: un host dedicado ofrece visibilidad y control adicionales sobre el servidor físico.

📉 Optimización de costos de cómputo

Optimización

Dimensionamiento adecuado (right-sizing)

Consiste en elegir el tamaño y tipo de instancia adecuados según el uso real de recursos de la carga de trabajo.

Idea rápida: evitar pagar por capacidad que no se necesita.

Optimización

Elasticidad y escalado

Ajustar la capacidad a la demanda permite responder a cambios de uso sin mantener recursos innecesarios todo el tiempo.

Idea rápida: usar más capacidad cuando se necesita y reducirla cuando deja de ser necesaria.

Optimización

Medición y monitoreo

Analizar métricas y patrones de uso ayuda a identificar recursos infrautilizados y oportunidades de ahorro.

Herramientas relacionadas: Amazon CloudWatch y AWS Cost Explorer.

📦 Contenedores y Docker

Contenedores

Contenedor

Unidad que empaqueta una aplicación junto con sus dependencias para ejecutarla de manera consistente en distintos entornos compatibles.

Idea rápida: llevar la aplicación y lo que necesita dentro de un paquete ejecutable.

Contenedores

Docker

Plataforma y conjunto de herramientas para crear, distribuir y ejecutar aplicaciones en contenedores.

Diferencia: una imagen es la plantilla; un contenedor es una instancia en ejecución de esa imagen.

Contenedores

Orquestación de contenedores

Automatiza tareas como desplegar, programar, escalar y mantener aplicaciones compuestas por contenedores.

Idea rápida: coordinar muchos contenedores en lugar de administrarlos uno por uno.

Contenedores

Amazon ECR

Registro administrado para almacenar, administrar y recuperar imágenes de contenedores.

Idea rápida: un repositorio de imágenes que después pueden utilizar los servicios de contenedores.

Contenedores

Amazon ECS

Servicio de orquestación para desplegar y administrar aplicaciones en contenedores.

Idea rápida: coordina dónde se ejecutan los contenedores y cómo se mantienen.

Contenedores

Amazon EKS

Servicio administrado que permite ejecutar Kubernetes en AWS.

Diferencia: utiliza Kubernetes como plataforma de orquestación.

Contenedores

AWS Fargate

Motor de cómputo sin servidor para ejecutar contenedores compatibles sin administrar los servidores subyacentes.

Idea rápida: ejecuta los contenedores sin tener que aprovisionar los servidores.

⚡ Otras opciones para ejecutar aplicaciones

Cómputo

AWS Lambda

Ejecuta código en respuesta a eventos sin que el usuario tenga que administrar servidores.

Idea rápida: ejecutar una función cuando ocurre algo, en lugar de mantener un servidor activo.

Cómputo

AWS Elastic Beanstalk

Facilita el despliegue y la administración de aplicaciones; AWS aprovisiona los recursos necesarios y permite gestionar el entorno.

Idea rápida: proporcionar la aplicación y dejar que el servicio simplifique su despliegue.

Comparación

¿Qué opción de cómputo elegir?

EC2 ofrece control sobre la instancia; Lambda ejecuta funciones por eventos; Elastic Beanstalk simplifica el despliegue de aplicaciones; ECS y EKS administran contenedores; Fargate evita administrar servidores para las tareas compatibles.

Regla rápida: elige según el nivel de control, la arquitectura de la aplicación y cuánto quieres administrar.

📒 Módulo 7 — Almacenamiento en AWS

💡 Idea principal: el módulo aborda almacenamiento de objetos (S3), bloques (EBS), archivos compartidos (EFS), seguridad y costos.

🗂️ Amazon S3 y sus clases de almacenamiento

Módulo 7 · S3

Amazon S3

Servicio administrado de almacenamiento en la nube que guarda datos como objetos dentro de buckets, con escalabilidad y alta durabilidad.

Idea rápida: guardar archivos en contenedores en línea.

S3

Bucket

Contenedor donde se almacenan objetos. Se crea en una región de AWS y luego se cargan los datos.

Idea rápida: una carpeta principal para organizar archivos.

Clase S3

S3 Estándar

Para datos de acceso frecuente, con alta durabilidad y disponibilidad en varias zonas.

Uso: datos que necesitan acceso rápido y frecuente.

Clase S3

S3 Estándar — Acceso poco frecuente (IA)

Adecuada para datos a los que se accede con poca frecuencia; la recuperación puede tener una tarifa asociada.

Uso: conservar datos que se recuperan ocasionalmente.

Clase S3

S3 Intelligent-Tiering

Traslada automáticamente los objetos entre niveles según sus patrones de acceso.

Uso: cuando los patrones de acceso cambian o no se conocen.

Clase S3

S3 Una zona — Acceso poco frecuente

Almacena datos en una sola zona de disponibilidad y ofrece un precio inferior al de S3 Estándar-IA.

Uso: datos poco frecuentes para los que es aceptable una sola zona.

Clase S3

Amazon S3 Glacier

Almacenamiento de archivo de bajo costo para copias de seguridad y conservación a largo plazo. Ofrece recuperación Expedited, Standard y Bulk.

Tiempos del material: Expedited, 1–5 minutos; Standard, 3–5 horas; Bulk, 5–12 horas.

Clase S3

S3 Glacier Deep Archive

Almacenamiento de menor costo para conservar archivos a largo plazo; el material menciona periodos de siete a diez años.

Recuperación: el material señala menos de 12 horas.

S3

Políticas de ciclo de vida

Permiten mover o eliminar objetos según su antigüedad y automatizar transiciones entre clases de almacenamiento.

Ejemplo: mover datos de S3 Estándar a Glacier y eliminarlos después del periodo definido.

S3 · Costos

Precios de Amazon S3

Dependen de la clase, volumen y tamaño de objetos, cantidad y tipo de solicitudes (GET, PUT, COPY, etc.) y transferencia de datos.

Según las diapositivas: se cobra almacenamiento por GB al mes; pueden cobrarse solicitudes y transferencias salientes. La transferencia entrante a S3 se muestra como gratuita.

Seguridad

Seguridad de S3 y Glacier

El material incluye cifrado en tránsito mediante SSL/TLS, cifrado del lado del servidor, control de acceso con IAM y cifrado AES-256 para Glacier con claves administradas.

Idea rápida: controlar quién accede a los datos y protegerlos durante el tránsito y almacenamiento.

🧱 Amazon EBS — Almacenamiento en bloques

Módulo 7 · EBS

Amazon EBS

Crea volúmenes de almacenamiento a nivel de bloques y los asocia a instancias EC2. Los volúmenes persisten independientemente de la instancia.

Usos: volúmenes de arranque, sistemas de archivos, bases de datos y aplicaciones empresariales.

Concepto

Almacenamiento en bloques

Divide los datos en bloques; al modificar una parte, puede actualizarse el bloque correspondiente.

Comparación: cambiar una pieza específica sin reemplazar todo el conjunto.

EBS · Tipos

Tipos de volúmenes EBS

El material distingue SSD de uso general, SSD con IOPS aprovisionadas y HDD optimizados para rendimiento o uso frío.

Elección: depende del rendimiento, IOPS y costo requerido.

EBS

Instantáneas (snapshots)

Capturan el estado de un volumen en un momento dado y permiten crear uno nuevo. El material indica que se calcula el costo por GB-mes de datos almacenados en S3.

Uso: respaldar volúmenes y facilitar su recuperación.

Seguridad

Cifrado de EBS

Los volúmenes EBS pueden cifrarse; las diapositivas indican que no tiene costo adicional.

Idea rápida: proteger los datos almacenados en los volúmenes.

EBS

Elasticidad de EBS

Permite aumentar la capacidad y cambiar entre distintos tipos de volumen según las necesidades.

Idea rápida: adaptar el almacenamiento cuando cambian los requisitos.

EBS · Costos

Costos de EBS

Se considera la cantidad de almacenamiento aprovisionada por mes y, según el tipo, las IOPS o solicitudes. El material indica que la transferencia entrante es gratuita y la saliente entre regiones genera cargos.

Recuerda: revisa el tipo de volumen, capacidad y transferencias.

📁 Amazon EFS — Sistema de archivos compartido

Módulo 7 · EFS

Amazon EFS

Sistema de archivos administrado y compartido en la nube de AWS, con capacidad elástica y escalabilidad hasta petabytes.

Usos: big data, análisis, procesamiento multimedia, administración de contenido, servidores web y directorios principales.

EFS · Arquitectura

Arquitectura de EFS

Utiliza destinos de montaje en zonas de disponibilidad dentro de una VPC; las instancias acceden al sistema mediante interfaces de red.

Idea rápida: varias instancias pueden acceder a un sistema de archivos compartido.

EFS · Recursos

Destino de montaje

Recurso de red que conecta las instancias al sistema de archivos. Incluye ID de subred y grupos de seguridad y debe estar en la misma VPC; el material indica uno por zona de disponibilidad.

También: los recursos pueden organizarse con etiquetas.

EFS

Compatibilidad de EFS

El material señala compatibilidad con NFS 4.0 y 4.1 y con AMI basadas en Linux para Amazon EC2.

Idea rápida: conectar sistemas compatibles mediante un protocolo de archivos de red.

📔 Módulo 8 — Bases de datos en AWS: RDS, DynamoDB, Redshift y Aurora

🗄️ Bases de datos administradas y no administradas

Módulo 8 · Concepto

Servicios no administrados vs. administrados

No administrados: el usuario administra el escalado, la tolerancia a errores y la disponibilidad. Administrados: estas capacidades suelen estar integradas en el servicio.

Comparación de la diapositiva 1: en el modelo no administrado se muestran herramientas de trabajo; en el administrado, una llave representa que AWS incorpora parte de esa administración.

Bases de datos relacionales

Desafíos de administrar una base de datos propia

Al ejecutar una base de datos relacional independiente, el usuario es responsable del mantenimiento del servidor y su huella energética, instalación y parches de software, copias de seguridad, alta disponibilidad, límites de escalabilidad, seguridad de los datos e instalación y parches del sistema operativo.

Idea rápida: una base de datos no administrada requiere atender tanto el software como la infraestructura que la sostiene.

Responsabilidades

¿Quién administra qué en un servicio administrado?

Usted administra: la optimización de las aplicaciones. AWS administra: instalación y parches del sistema operativo, instalación y parches del software de base de datos, copias de seguridad, alta disponibilidad, escalado, energía, servidores, bastidores, pilas y mantenimiento del servidor.

Importante: el servicio administrado reduce las tareas de infraestructura, pero la optimización de la aplicación continúa a cargo del usuario.

🟦 Amazon RDS — Base de datos relacional administrada

Módulo 8 · RDS

Amazon RDS

Servicio administrado que configura y opera una base de datos relacional en la nube.

Flujo del diagrama: los usuarios se conectan a servidores de aplicaciones y estos acceden a una instancia de Amazon RDS dentro de la nube de AWS.

RDS · Instancias

Instancias de base de datos

Son los bloques de creación básicos de Amazon RDS. La clase de instancia determina recursos como CPU, memoria y rendimiento de red. El almacenamiento de la instancia puede ser magnético, de uso general (SSD) o de IOPS aprovisionadas.

Idea rápida: la instancia aporta capacidad de cómputo y almacenamiento para ejecutar la base de datos.

RDS · Motores

Motores de bases de datos de RDS

La diapositiva enumera MySQL, Amazon Aurora, Microsoft SQL Server, PostgreSQL, MariaDB y Oracle como motores de bases de datos.

Recuerda: el motor es una de las características que se consideran al elegir y calcular el costo de una instancia.

RDS · Alta disponibilidad

Implementación Multi-AZ

La arquitectura mostrada distribuye la instancia principal de Amazon RDS y una instancia en espera en distintas zonas de disponibilidad, dentro de una VPC. La aplicación se conecta a la base de datos a través de la red.

Diagrama de la página 7: muestra una subred pública con Amazon EC2 y la aplicación, y subredes privadas con la instancia RDS principal y la instancia en espera, sincronizadas.

RDS · Rendimiento

Réplicas de lectura de Amazon RDS

Ofrecen replicación asíncrona y pueden promoverse a instancia principal si es necesario. Se utilizan para cargas de trabajo de base de datos con muchas lecturas y para reasignar consultas de lectura.

Diagrama de la página 8: la instancia principal recibe la escritura y los datos se replican hacia una instancia de réplica de lectura. El material menciona su disponibilidad para MySQL.

RDS · Casos de uso

¿Para qué se utiliza Amazon RDS?

Aplicaciones web y móviles: alto rendimiento, escalabilidad de almacenamiento masivo y alta disponibilidad. Comercio electrónico: base de datos de bajo costo, seguridad de datos y solución completamente administrada. Juegos móviles y en línea: crecimiento rápido, escalado automático y monitoreo de bases de datos.

RDS · Criterios de elección

Cuándo utilizar o no utilizar Amazon RDS

Utilícelo cuando: la aplicación necesite transacciones o consultas complejas, una tasa media-alta de consulta o escritura (hasta 30 000 IOPS: 15 000 lecturas y 15 000 escrituras, según la diapositiva), no más de una partición o nodo de trabajo y alta durabilidad.

No lo utilice cuando: se requieran tasas masivas de lectura o escritura (el ejemplo indica 150 000 escrituras por segundo), la fragmentación por grandes volúmenes o demandas de rendimiento sea un problema, basten solicitudes GET o PUT simples que pueda manejar NoSQL, o se necesite personalizar el sistema de administración relacional (RDBMS).

💰 Amazon RDS — Facturación y factores de costo

RDS · Costos

Facturación por horas de reloj

Se generan cargos por la ejecución de los recursos. Entre las características físicas de la base de datos que influyen en el costo se encuentran el motor, el tamaño y la clase de memoria.

RDS · Costos

Tipo de compra y cantidad de instancias

Bajo demanda: capacidad de cómputo por hora. Reservadas: pago inicial y reducido para instancias reservadas durante 1 o 3 años. También se pueden aprovisionar varias instancias para gestionar cargas máximas.

RDS · Costos

Almacenamiento y copias de seguridad

El material indica que el almacenamiento de copias de seguridad de hasta el 100 % del almacenamiento de la base de datos no tiene cargo para bases de datos activas. Se cobra por GB al mes el almacenamiento de copias de seguridad de instancias terminadas y el almacenamiento adicional.

Almacenamiento adicional: se suma al almacenamiento aprovisionado y se cobra por GB al mes.

RDS · Costos

Solicitudes, implementación y transferencia

La cantidad de solicitudes de entrada y salida a la base de datos influye en el costo. Los cargos por almacenamiento y operaciones de E/S varían según la implementación en una o varias zonas de disponibilidad.

Transferencia: las transferencias entrantes de datos se muestran sin cargo; las transferencias salientes tienen cargos por niveles.

⚖️ Bases de datos relacionales y no relacionales

Comparación

Relacional (SQL) vs. no relacional (NoSQL)

Relacional: organiza los datos en filas y columnas, utiliza esquemas fijos, consultas SQL y escalabilidad vertical. No relacional: puede utilizar estructuras clave-valor, documentos o gráficos; maneja esquemas dinámicos, se centra en la recopilación de documentos y permite escalabilidad horizontal.

Ejemplo de la diapositiva 15: la tabla relacional presenta ISBN, título, autor y formato en columnas; el ejemplo NoSQL representa esos mismos datos como atributos de un documento.

🟪 Amazon DynamoDB — Base de datos NoSQL

Módulo 8 · DynamoDB

Amazon DynamoDB

Servicio de base de datos NoSQL rápido y flexible para cualquier escala. Sus características mostradas incluyen tablas NoSQL, almacenamiento prácticamente ilimitado, elementos que pueden tener atributos diferentes, consultas de baja latencia y rendimiento escalable de lectura o escritura.

DynamoDB · Componentes

Tablas, elementos y atributos

Los componentes principales de DynamoDB son las tablas, los elementos y los atributos. Una tabla contiene elementos y cada elemento está formado por atributos.

Comparación: tabla = conjunto de registros; elemento = registro individual; atributo = dato o propiedad del elemento.

DynamoDB · Claves

Claves principales: única y compuesta

DynamoDB admite dos tipos diferentes de claves principales: clave de partición y clave de partición y organización (clave compuesta). La clave compuesta combina la clave de partición con un criterio de ordenación.

Diagrama de la página 18: compara una clave única con una clave compuesta y señala qué parte identifica la partición, cuál establece el orden y cuáles son los atributos.

Módulo 8 · Redshift

Amazon Redshift

Servicio presentado para trabajar con un almacén de datos. El material señala que construir un almacén de datos por cuenta propia puede ser una tarea compleja y costosa.

Arquitectura de procesamiento en paralelo

Los clientes SQL y las herramientas de inteligencia empresarial envían consultas al nodo principal. Este coordina los nodos informáticos densos, que cuentan con núcleo virtual, RAM y disco local. Los nodos devuelven resultados intermedios al nodo principal para su agregación final.

Administrar, monitorizar y escalar

La diapositiva de automatización y escalado destaca tres actividades: administrar, monitorizar y escalar.

Beneficio señalado: estas tareas permiten centrarse en los datos y en el negocio.

Redshift · Compatibilidad

Compatibilidad con herramientas

Amazon Redshift es compatible con clientes SQL y herramientas de inteligencia empresarial que el usuario ya conoce y utiliza.

Diagrama de la página 22: representa la conexión entre Redshift y los clientes o herramientas de análisis.

Redshift · Casos de uso

Casos de uso de Amazon Redshift

Almacenamiento de datos empresariales, migración a un ritmo cómodo para los clientes, experimentación sin un gran costo o compromiso inicial, respuesta más rápida a las necesidades del negocio y big data.

Otros puntos del material: precios bajos para clientes pequeños, servicio administrado para facilitar implementación y mantenimiento, y mayor enfoque en los datos que en administrar la base de datos.

Redshift · SaaS

Uso de Redshift en software como servicio (SaaS)

Los clientes SaaS pueden escalar la capacidad del almacenamiento de datos a medida que crece la demanda, incorporar funcionalidad de análisis en sus aplicaciones y reducir los costos de hardware y software.

🟦 Amazon Aurora — Base de datos relacional creada para la nube

Módulo 8 · Aurora

Amazon Aurora

Base de datos relacional de clase empresarial, compatible con MySQL o PostgreSQL y creada para la nube. Automatiza tareas que requieren mucho tiempo, como aprovisionamiento, implementación de parches, copias de seguridad, recuperación, detección de errores y reparación.

Aurora · Beneficios

Beneficios de Amazon Aurora

🧭 Comparación y elección de servicios

Comparación

RDS, DynamoDB, Redshift y Aurora

Amazon RDS: base de datos relacional administrada. Amazon DynamoDB: base de datos NoSQL rápida y flexible. Amazon Redshift: almacén de datos y procesamiento analítico en paralelo. Amazon Aurora: base de datos relacional de clase empresarial, compatible con MySQL y PostgreSQL y creada para la nube.

Regla rápida: RDS para bases relacionales administradas; DynamoDB para NoSQL; Redshift para almacenes de datos y análisis; Aurora para una base relacional de nube con las características indicadas en el material.
